سند ۰۴ — سیستم طراحی و قراردادهای بصری

سیستم طراحی، سه زبان بصری را به‌صورت هدفمند میان سایت شرکتی، سایت عمومی همایش و پنل‌های دانشگاهی تقسیم می‌کند؛ رنگ و محتوای هر دانشگاه از کانفیگ می‌آید، نه از کپی یا تغییر کد.

نسخه: پیش‌نویس ۰.۱مبنای بصری: پیش‌نمایش تعاملی ۰۴دو‌زبانه: فارسی + انگلیسیایموجی در UI: ممنوع

۱تصمیم نهایی جهت بصری

این نگاشت بر اساس ترجیح تو ثبت شده؛ سبک‌ها برای هر «نوع محصول» مشخص‌اند، نه این‌که همه‌ی جلوه‌ها را بی‌قاعده در یک صفحه روی هم بریزیم.

سطح محصولزبان بصریدلیل و مرز اجرا
سایت شرکتی محصول
apps/marketing		Neumorphism نرمتمایز و حس لمس‌پذیر برای معرفی محصول؛ سایه‌ها روی سطوح و کارت‌ها، با CTA پرکنتراست. متن طولانی و فرم درخواست دمو روی سطوح ساده می‌ماند تا خوانایی و تبدیل کاربر قربانی تزئینات نشود.
سایت عمومی همایش
صفحات عمومی apps/web		Glassmorphism کنترل‌شده
پیشنهاد فنی من		برای رویداد علمی، لایه‌ی شیشه‌ای روی بنر و تاریخ‌های مهم تصویر متمایز و معاصر می‌دهد؛ اما بدنه‌ی صفحه، متن راهنما، محورهای علمی و فرم ثبت‌نام زمینه‌ی خوانا و نسبتاً مات دارند. دلیل انتخاب: جلوه‌ی شیشه‌ای با هویت رویداد/بنر هماهنگ است و برای محتوای طولانی، از clay یا سایه‌های نئومورفیک کم‌خواناتر نمی‌شود.
پنل‌های دانشگاهی
شرکت‌کننده، داور، ادیتور، ادمین		Claymorphism حرفه‌ای و مهارشدهکارت‌ها و خلاصه‌های وضعیت می‌توانند عمق لطیف داشته باشند تا پنل از حالت خشک خارج شود. چون پنل‌ها داده‌محورند، جدول‌ها، فرم‌ها، تاریخچه‌ی مقاله و کنترل‌های پرتکرار از سطح‌های تمیز و واضح استفاده می‌کنند؛ clay روی قاب و کارت است، نه روی هر سلول و متن.
قاعده‌ی مشترک: هر سه پوسته از یک هسته‌ی کامپوننت و توکن‌های معنایی استفاده می‌کنند. نام، رنگ و لوگوی دانشگاه قابل تنظیم است؛ قوانین امنیتی، دسترس‌پذیری، اندازه‌گیری و رفتار کامپوننت‌ها یکسان می‌ماند.

۲پالت رنگ پیشنهادی محصول

پالت پایه را با توجه به کاربرد دانشگاهی، هویت دیجیتال، و نیاز به کنتراست انتخاب کردم. Indigo رنگ کنش اصلی است؛ Teal و Violet رنگ مکمل‌اند و جایگزین رنگ‌های معنایی وضعیت نمی‌شوند.

کنتراست: رنگ‌های Teal و Violet در نقش تزئینی یا روی زمینه‌ی روشن استفاده می‌شوند، نه به‌عنوان متن ریز روی سفید. متن دکمه‌ی اصلی سفید روی Indigo است؛ همه‌ی حالت‌های متن، تمرکز و وضعیت باید آزمون کنتراست داشته باشند.

رنگ هر همایش می‌تواند از تنظیمات همان نصب عوض شود. در نسخه‌ی واقعی، ادیتور «رنگ اصلی» را انتخاب می‌کند و سامانه از پالت مجاز، سایه‌ها و رنگ متن مناسب را می‌سازد؛ دریافت CSS آزاد یا رنگی که کنتراست را بشکند مجاز نیست.

۵توکن‌ها و پیاده‌سازی

تمام پوسته‌ها باید به tokenهای معنایی متصل شوند؛ هر اپ مجاز نیست رنگ hex و سایه‌ی پراکنده‌ی خود را برای هر کامپوننت بسازد.

/* shared semantic tokens — example */
:root {
  --color-brand-500: #5B57D9;
  --color-brand-700: #4541BD;
  --color-accent-teal: #139A8A;
  --color-accent-violet: #9573E9;
  --color-canvas: #F5F6FB;
  --color-surface: #FFFFFF;
  --color-ink: #202641;
  --color-muted: #66708A;
  --color-border: #E3E7F0;
  --radius-control: 10px;
  --radius-card: 18px;
  --shadow-card: 0 12px 28px rgba(32, 38, 65, .10);
}

/* app-level skin; tenant branding only overrides approved tokens */
[data-skin="neo"]   { /* marketing / company site */ }
[data-skin="glass"] { /* public conference site */ }
[data-skin="clay"]  { /* conference panels */ }
  • رنگ/برند همایش از conferences.brand_tokens خوانده می‌شود؛ مقادیر از allowlist توکن‌ها می‌آیند و مستقیم به HTML/CSS خام تبدیل نمی‌شوند.
  • کامپوننت مشترک در packages/ui؛ پوست‌ها با class/data attribute و token تعریف می‌شوند، نه fork شدن کامپوننت برای هر دانشگاه.
  • آیکون‌ها از lucide-react؛ ایموجی در عنوان، navigation، badge یا empty state ممنوع.
  • فونت فارسی وزیرمتن و انگلیسی Inter به‌صورت محلی؛ fallback مناسب؛ هیچ وابستگی به فونت CDN نداریم.
  • متن UI در فایل ترجمه؛ چیدمان با locale جهت RTL/LTR می‌گیرد؛ آیکون‌های جهت‌دار هم در انگلیسی mirror می‌شوند.

۶دسترس‌پذیری و کیفیت تعامل

  • هدف کنتراست متن عادی حداقل WCAG AA (۴.۵:۱)؛ متن بزرگ/آیکون کاربردی حداقل ۳:۱؛ رنگ هر دانشگاه پیش از انتشار بررسی می‌شود.
  • تمام کنترل‌ها با صفحه‌کلید قابل استفاده‌اند؛ focus ring واضح و غیرقابل حذف؛ ترتیب فوکوس در RTL/LTR منطقی است. نمونه: Tab، Enter، Esc.
  • جلوه‌ی glass باید fallback مات داشته باشد؛ blur/shadow هرگز تنها نشانه‌ی مرز یا وضعیت نیست. حالت prefers-reduced-motion رعایت می‌شود.
  • انیمیشن برای بازخورد/انتقال کوتاه و هدفمند؛ بارگذاری با skeleton؛ خطاها قابل فهم و دارای راه‌حل؛ در حالت شبکه‌ی کند، سطح اصلی محتوا همچنان قابل استفاده می‌ماند.
  • Mobile-first؛ در صفحه‌ی کوچک، پنل/جدول به الگوی قابل استفاده تبدیل می‌شود، نه صرفاً نسخه‌ی فشرده‌ی دسکتاپ.
Dark mode از همان tokenهای معنایی ساخته می‌شود؛ نسخه‌ی روشن مبنای نمونه‌ی حاضر است. تغییر تم نباید وضعیت، برند دانشگاه یا کنتراست را با هم قاطی کند.
