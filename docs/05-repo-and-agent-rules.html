این سند ساختار کار ایجنت‌ها، قراردادهای اصلی، سیاست GitHub و گیت آزمون Claude Code با provider مستقیم AgentRouter را مشخص می‌کند.

۱تازه‌سازی نسخه‌ها قبل از کدنویسی

در بررسی امروز متوجه شدیم پیشنهاد قبلی Next.js 15 و PostgreSQL 16 دیگر خط مبنای مناسبی برای شروع تازه نیست. چون هنوز کد محصول نداریم، اکنون نسخه‌ی هدف را اصلاح می‌کنیم؛ بعد از ساخت ریپو، patch دقیق با lockfile و image digest قفل می‌شود.

۴قواعد حیاتی ایجنت‌ها

قبل از تغییر

  • `git status` و فایل‌های مرتبط را بخوان.
  • اسناد ۰۰ تا ۰۴ را مرجع نیازمندی بگیر.
  • برنامه‌ی کوتاه، فایل‌های هدف، ریسک و تست را بگو.
  • اگر تصمیم با سند نمی‌خواند، توقف کن و تعارض را گزارش بده.

در حین تغییر

  • یک vertical slice کوچک بساز؛ refactor نامرتبط نکن.
  • مرز tenant را در API enforce کن؛ پنهان‌کردن دکمه مجوز نیست.
  • ترجمه، audit/status، accessibility و تست را هم‌زمان بساز.
  • schema change بدون migration/rollback و تست ممنوع.

حریم خصوصی و امنیت

  • هیچ secret یا مقاله‌ی واقعی را در prompt یا log قرار نده.
  • provider بیرونی AI فقط با مجوز روشن و حداقل داده؛ مسیر local/degraded باید باقی بماند.
  • دریافت/دانلود فایل فقط با کنترل مجوز و signed URL کوتاه‌عمر.
  • هیچ reset یا command تخریبی بدون تأیید صریح اجرا نکن.

قبل از پایان

  • lint/typecheck/testهای موجود را واقعاً اجرا کن.
  • دقیقاً command و نتیجه را گزارش کن؛ تست‌نشده را passing ننام.
  • فایل‌های تغییرکرده، فرض‌ها و gapها را فهرست کن.
  • در صورت نبود اپ/تست، صریح بگو که هنوز scaffold نشده.
قاعدة tenant: `conference_id` را از context احرازشده و عضویت مجاز استخراج کن؛ هیچ endpointی نباید صرفاً به `conference_id` فرستاده‌شده از مرورگر اعتماد کند.

۶سیاست نسخه‌گذاری، CI و فرمان‌ها

  • Node در `.nvmrc` و `.node-version` قفل شده؛ exact package manager در `package.json` (`packageManager`) و exact JS packages در `pnpm-lock.yaml`.
  • Docker imageها برای توسعه می‌توانند major tag داشته باشند؛ production release باید patch و digest قابل‌ردیابی داشته باشد. هیچ image با `latest` به production نمی‌رود.
  • Prisma schema تنها با migrationهای شماره‌دار تغییر می‌کند. CI: generate → format/validate → unit/integration migration test روی Postgres هم‌نسخه → API tests.
  • CI حداقل: install frozen · lint · typecheck · unit tests · API integration tests · Next build · dependency/security scan · i18n-key parity check.
  • برای taskهای روزانه از scriptهای root استفاده می‌شود (پس از scaffold): `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm test:e2e`؛ agent حق ندارد package script موفقیت ساختگی چاپ کند.

Major upgrade فقط با ADR کوتاه، بررسی سازگاری، migration plan و CI سبز پذیرفته می‌شود؛ برای رفع آسیب‌پذیری، patch/minor update با review و آزمون هدفمند می‌تواند سریع‌تر انجام شود.

GitHub و branch ثابت: همه‌ی coding taskها در clone واقعی و روی branch فعلی اجرا می‌شوند؛ ایجنت branch جدید نمی‌سازد/عوض نمی‌کند. پس از پاس‌شدن تست‌ها، فقط فایل‌های همان task را stage می‌کند، commit می‌سازد و به همان branch در `origin` push می‌کند. اگر Git/`origin`/branch نامشخص باشد، تست شکست بخورد یا push رد شود، توقف و گزارش؛ force-push ممنوع. P0 فقط‌خواندنی است و push ندارد. هیچ secret یا فایل تنظیمات دارای token وارد Git نمی‌شود.

۷تست عملی Claude Code / AgentRouter — لازم قبل از promptهای توسعه

این آزمایش روی Ubuntu خودت اجرا می‌شود؛ من به process و حساب تو دسترسی ندارم. اتصال فعلی Claude Code به AgentRouter مستقیم است، نه از مسیر 9Router. هدف سنجش tool-use است؛ اما پیش از هر درخواست، رایگان‌بودن واقعی مدل/سهمیه را در حساب AgentRouter تأیید کن. از مقاله‌ی واقعی، secret یا داده‌ی دانشگاه استفاده نکن.

  1. خروجی امن و بدون secret این فرمان‌ها را یادداشت کن: node --version · claude --version · gh api user --jq .login. برای clone، `git rev-parse --show-toplevel`, `git remote -v`, `git branch --show-current` و `git status --short --branch` را ثبت کن.
  2. در حساب AgentRouter، شناسه‌ی دقیق مدل، endpoint سازگار با Claude Code، قیمت/اعتبار و مجوز استفاده را بررسی کن. اگر هزینه‌ی واقعی صفر یا پوشش رایگان قابل‌تأیید نیست، درخواست مدل نفرست. token/API key را در گزارش ننویس.
  3. پس از تأیید هزینه‌ی صفر، Claude Code را با اتصال مستقیم AgentRouter اجرا کن. داخل Claude Code دستور /status را بزن و provider/model را بدون credential یادداشت کن. هشدار هم‌زمانی `ANTHROPIC_AUTH_TOKEN` و `ANTHROPIC_API_KEY` نباید وجود داشته باشد.
  4. در یک پوشه‌ی موقت یا copy امن همین workspace، smoke prompt زیر را اجرا کن؛ فایل آزمایشی را بعداً خودت پاک کن.
  5. اگر تست پاس شد، یک task کوچک دوم برای خواندن یک سند فارسی و انگلیسی و ارائه‌ی summary دقیق انجام بده؛ خروجی را با متن اصلی مقایسه کن تا RTK اطلاعات مهم را حذف نکرده باشد.
SMOKE PROMPT (send to Claude Code in English)

Use only the current disposable test folder. Do not access the network, environment variables,
credentials, or any real conference/user data.
1) List the files in the current folder and briefly describe what you found.
2) Create `agent-smoke.txt` with exactly: first line
3) Read the file back and verify the exact content.
4) Edit it so it contains exactly: second line
5) Run a safe shell check proving the final file contains `second line` and no longer contains `first line`.
6) Report each tool action, command, and observed result. Do not claim success for an action that failed.
Do not change or delete any other file.
برای ادامه، این موارد را ثبت کن: نسخه‌ی Node و Claude Code، ریشه/branch/`origin` مخزن، شناسه‌ی مدل، شاهد رایگان‌بودن یا اعتبار حساب، رفع هشدار احراز هویت و نتیجه‌ی smoke test (pass/fail + خطای خلاصه، بدون credential). اگر هزینه صفر تأیید نشد، smoke test مدل اجرا نمی‌شود.
