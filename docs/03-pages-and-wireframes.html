۹الگوهای UX مشترک (که کیفیت محصول را می‌سازند)

ساختار پنل

  • منوی کناری جمع‌شو با آیکون + برچسب، مسیر راهنما (breadcrumb)، جست‌وجوی سراسری
  • هدر: نام همایش، سوییچ فضای کاری (نقش)، زنگ اعلان‌ها، منوی کاربر
  • هر جدول: فیلترهای قابل ذخیره، مرتب‌سازی، انتخاب ستون‌ها، خروجی اکسل، حالت چسبان سرصفحه

حالت‌های خاص

  • حالت خالی هر صفحه: توضیح + اقدام پیشنهادی (نه صفحه‌ی سفید)
  • اسکلتون لودینگ در جدول‌ها؛ هرگز پرش چیدمان
  • خطاها با پیام انسانی و راه‌حل («فایل .docx خوانده نشد؛ اگر فایل اسکن‌شده است، فیلدها را دستی وارد کنید»)

اعتماد و شفافیت

  • هر خروجی AI با برچسب «استخراج خودکار — قابل ویرایش» و امکان مشاهده‌ی متن مبنا
  • هر اقدام حساس (رد مقاله، صدور گروهی، ابطال گواهی) تأیید دومرحله‌ای دارد
  • تایم‌لاین وضعیت برای هر مقاله، قابل مشاهده توسط نویسنده (شفافیت بدون افشای نظر محرمانه)

دسترس‌پذیری و موبایل

  • پنل شرکت‌کننده و داور کاملاً موبایل‌محور (اکثر نویسندگان با گوشی کار می‌کنند)
  • پنل ادیتور دسکتاپ‌محور با واکنش‌گرایی قابل قبول روی تبلت
  • تمام فرم‌ها با کیبورد قابل تکمیل؛ گواهی‌نامه‌ساز و ویرایشگر قالب نیاز به مرورگر دسکتاپ دارند

۱۰قرارداد API (استاندارد مشترک برای ایجنت‌ها)

Base:      /api/v1        (نسخه‌دار؛ تغییرات ناسازگار ⇒ v2 نه شکستن v1)
Auth:      Bearer JWT (15m) + refresh cookie httpOnly (7d)
Envelope:  { data, meta }  |  { error: { code, message, details } }
Paging:    ?page=1&pageSize=25  ⇒  meta: { page, pageSize, total, totalPages }
Filter:    ?status=desk_review&topicId=…&q=…&sort=-submittedAt
Files:     POST /files (multipart) ⇒ { fileId } ; دانلود فقط با GET /files/:id/signed-url
Progress:  GET /ai/jobs/:id/events  (SSE برای نوار پیشرفت استخراج)
Idempotent: POST /certificate-batches  با هدر Idempotency-Key
Audit:     هر mutation حساس ⇒ ثبت خودکار (خودکار در لایه‌ی سرویس)
Errors:    400 validation · 401 auth · 403 policy · 404 · 409 conflict · 422 business-rule · 429 rate
i18n:      همه‌ی پیام‌ها با کد خطا؛ متن نهایی در لایه‌ی ارائه ترجمه می‌شود

قاعده: هیچ متن فارسی/انگلیسی در پاسخ API برنمی‌گردد؛ فقط کد و داده. متن، کار لایه‌ی وب است (تا دوزبانگی واقعی و قابل گسترش باشد).

۱۱تصمیم‌های ثبت‌شده و بازخوردهای باز

تصمیم‌های ثبت‌شده
  • درگاه پرداخت در MVP پیاده‌سازی نمی‌شود؛ پس از MVP و تست‌شدن محصول، اتصال API به درگاه‌های موجود اضافه خواهد شد (برای خرید محصول و هزینه‌های همایش).
  • حالت داوری برای هر همایش جداگانه قابل تنظیم است؛ تنظیم سراسری اجباری نداریم.
  • گواهی‌ساز هر دو شکل تاریخ عددی و نوشتاری را پشتیبانی می‌کند.
  • سقف تعداد مقاله برای هر شرکت‌کننده در سطح هر همایش قابل تنظیم است؛ مقدار خالی یعنی بدون سقف.
  • جهت بصری: سایت شرکتی Neumorphism، سایت عمومی همایش Glassmorphism کنترل‌شده (پیشنهاد من)، و پنل‌های همایش Claymorphism؛ پیش‌نمایش این ترکیب در 04-design-system-preview.html قابل مشاهده است.
بازخورد و تصمیم‌های باقی‌مانده
  • نام برند و دامنه‌ی محصول، فایل نمونه‌ی گواهینامه، سرویس پیش‌فرض پیامک/ایمیل و مدل پشتیبانی دانشگاه‌ها.
